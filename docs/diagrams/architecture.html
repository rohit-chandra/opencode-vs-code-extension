How OpenCode Hub is put together

One chat in front of five engines, and no server of ours in between.

1 Chat webview sandboxed: no network access, holds no secrets
Chat UI A small Preact app: messages, the composer, slash-command and file pickers, the sessions, MCP, usage and feedback panels.
Oki, the companion Three.js in a separate bundle, loaded after the chat is usable. Acts out what the session is doing.
postMessage  the full state once, then small patches and stream events grouped per frame
2 Extension host Node.js inside VS Code
ChatViewProvider Shows the chat in the side bar and in an editor tab, both at once if you like.
ChatController Owns the one view state. Runs built-in slash commands, prepares attachments, routes approvals, and decides what the webview hears about.
UsageLedger Tokens and cost per session, model, provider and day. Counted once per message.
On your disk only Sessions and usage in your VS Code profile. API keys in the OS keychain.
One Engine interface  prompts go down, the same normalized events come up from every engine
3 Engines interchangeable, switch with /engine
opencodeThe default. Agents, custom commands, undo, share.
Claude CodeYour Claude plan, or an API key.
CodexYour ChatGPT plan, or an API key.
Direct BYOKYour own keys, or a local model.
CopilotVS Code's language models.
4 Outside the extension your CLIs, your accounts, your keys
opencode serveLocal HTTP and an event stream on 127.0.0.1, random password per run.
claudeOne CLI run per turn, JSON lines out. Asks the chat before tools.
codexOne CLI run per turn, JSON lines out, inside its sandbox.
Model APIsOpenAI-compatible, Anthropic, OpenRouter, Hugging Face, Ollama, LM Studio.
Language Model APIGitHub Copilot and models other extensions register.
MCP serversstdio or HTTP, through the extension's own MCP client. Each tool call asks you first.
owns the state part of the extension yours: data on your disk, and the tools and services you chose
